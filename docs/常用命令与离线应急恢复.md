# sing-box 常用命令与离线应急恢复

以下命令适用于本仓库安装的 Debian 版本，使用 root 执行。命令调用本机已经安装的 systemd 服务和管理文件，不需要联网、拉取仓库或打开交互菜单。

## 查看服务、版本与日志

```bash
# sing-box 是否运行、是否设置为开机启动
systemctl is-active sing-box.service
systemctl is-enabled sing-box.service

# 版本与最近日志
sing-box version
journalctl -u sing-box.service -n 100 --no-pager

# 物理网卡隔离服务状态与本次启动日志
systemctl is-active singbox-uplink-isolation.service
systemctl is-enabled singbox-uplink-isolation.service
journalctl -u singbox-uplink-isolation.service -b -n 100 --no-pager

# 查看主机和 uplink 命名空间中的接口、路由
ip -br address
ip route
ip netns list
ip netns exec sb-uplink ip -br address
ip netns exec sb-uplink ip route
```

## 节点断网时关闭代理并恢复直连

如果代理节点失联，且需要让服务器暂时通过普通上游网络访问外网（例如拉取修复文件），执行：

```bash
systemctl disable --now singbox-manager-telegram.timer 2>/dev/null || true
systemctl stop singbox-manager-telegram.service 2>/dev/null || true
systemctl disable --now sing-box.service
```

这会停止代理和 Telegram 定时监测，并阻止 sing-box 在重启时自动启动。服务停止钩子会清理 sing-box 的透明代理规则。物理网卡仍留在 `sb-uplink` 命名空间，主机继续通过 veth 和 uplink NAT 联网；按本仓库当前网络规则，这会让普通流量直接经服务器上游出口访问互联网，目标站点会看到服务器的真实公网出口 IP。

若只想临时停止代理、但保留 sing-box 下次开机自动启动，可将上面第三条改为：

```bash
systemctl stop sing-box.service
```

恢复节点后，如之前执行了 `disable --now`，可用以下命令重新启用服务：

```bash
systemctl enable sing-box.service
```

确认代理配置和节点可用后，再从管理菜单启用代理。不要在节点仍不可用时直接启动，以免再次失去代理连接。

## 网卡隔离服务与代理服务的区别

`sing-box.service` 管理代理；`singbox-uplink-isolation.service` 管理物理网卡的网络命名空间隔离。关闭代理不需要停止网卡隔离服务。若网卡隔离服务意外处于 inactive，而隔离配置仍存在，可在本机尝试重新启用：

```bash
systemctl enable singbox-uplink-isolation.service
systemctl start singbox-uplink-isolation.service
```

启动前可先检查 `systemctl cat singbox-uplink-isolation.service`，确认 `ExecStart` 指向的本机 `network_isolation.py` 文件存在。若显示脚本不存在或启动报错，不要通过 SSH 盲目重启网络服务；应使用云厂商控制台检查安装路径和网卡状态。

`singbox-uplink-isolation.service` 是一次性启动服务，没有用于撤销网卡迁移的 `ExecStop`。因此，单独执行 `systemctl stop` 或 `disable` **不会**把物理网卡移回主机，也不会自动恢复原地址和默认路由。不要把这两条命令当作取消隔离的方法。

## 将物理网卡恢复到主机网络命名空间

如果要彻底撤销网卡隔离，本仓库安装的本地恢复程序无需联网即可执行：

```bash
/usr/bin/python3 /usr/local/lib/singbox-manager/network_isolation.py disable
```

该操作会把物理网卡及保存的地址、默认路由恢复到主机，并停用隔离服务。**建议从本地或云厂商控制台执行**，网络管理器重启或地址恢复时 SSH 连接可能中断。不要用简单的 `ip link set ... netns 1` 替代：那不会恢复保存的 IP、网关、DNS 和路由。

如果提示恢复程序不存在，先执行：

```bash
systemctl cat singbox-uplink-isolation.service
ls -l /usr/local/lib/singbox-manager/network_isolation.py
```

以服务实际使用且存在的本地程序路径为准；不要为了恢复网络从不可信来源下载脚本。

## 重新启动隔离服务的检查

确认隔离状态：

```bash
systemctl status singbox-uplink-isolation.service --no-pager
ip netns exec sb-uplink ip -br link
```

如果目标是恢复普通直连，保持隔离服务运行并按前面的步骤关闭 sing-box；如果目标是让物理网卡回到主机，则使用本地 `network_isolation.py disable`。两种操作解决的问题不同。
